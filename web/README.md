# web/ — experience plane, the React front end

This folder holds the browser application shell: React, TypeScript and Vite, with no feature UI.

## Rules

- The front end reaches the backend only over HTTP (BE-06).
- No dependency or asset is loaded from a third-party host (FE-05).
- The browser computes no displayed number; it only formats the values it receives.

## Commands

Run from `web/`. `npm ci` installs from `package-lock.json` and needs the network once; every other command below works without it.

- `npm ci` installs the exact locked dependencies.
- `npm run dev` starts the development server on `127.0.0.1` (port 5173, strict). It is a developer command and is not part of the checks.
- `npm run build` type-checks with `tsc --noEmit` and runs the production build into `dist/`.
- `npm run check` runs the layout check, the exact-version check (FE-01), the import-boundary check (FE-07) and the third-party host scan of the sources (FE-05, DES-24).
- `npm run check:hosts:dist` runs the host scan again over the build output; run it after `npm run build`.
- `npm run check:dev` reads the entry script named in `index.html`, starts the development server on a free loopback port (a port that already answers is reported as a failure), checks that the served page names that script and that the script is served as JavaScript, scans the page for third-party hosts and stops the server.
- `npm run test:checks` runs the tests of the checks above and of the shell files, each with a planted violation.

## Pins

Seven packages, all exact (no range): `react` 19.3.1, `react-dom` 19.3.1 and `vite` 8.3.8 are pack pins, to be confirmed at slice S1; `typescript` 6.0.3, `@vitejs/plugin-react` 6.3.0, `@types/react` 19.3.0 and `@types/react-dom` 19.3.0 are assumptions taken from the package registry on 2026-11-11, recorded in [OPEN_ITEMS.md](../OPEN_ITEMS.md) (OI-42). TypeScript 7 is to be re-evaluated at slice S1. `package-lock.json` is generated by `npm install --package-lock-only` and installed by `npm ci`; `node_modules/` and `dist/` are never committed.

## Limits of the checks

- The import-boundary check reads the script files (`.ts .tsx .mts .cts .js .jsx .mjs .cjs`) and style files (`.css .scss .sass .less .styl .pcss`) under `src/`, `tests/` and `eslint-rules/`, the file `vite.config.ts`, and `tsconfig.json`. It does not read `scripts/`. In script files it reads these literal forms: `import ... from`, `export ... from`, `import 'x'`, `require('x')`, `import('x')`, `new URL('x', import.meta.url)`, `import.meta.glob` with a string or an array of strings, and `/// <reference path>` and `/// <reference types>`; strings are read in single or double quotes in every form above, and as backticks without `${` only inside `import()`, `new URL()`, `import.meta.glob()` and `require()`. It reports a template literal with `${`, a name, or any other non-literal first argument of `import()` and `require()` (and a template literal with `${` in `new URL()`). Text inside a comment of a script file is not judged. It is not a JavaScript parser: a regular-expression literal or JSX text that holds a quote can hide the rest of that line, and a path built at run time, a `new Worker` path, a `new URL` or `import.meta.glob` with a name, Sass `@use`, and `vite.config.ts` settings are not read. In style files it reads `@import` and `url()`, and comments are not stripped there.
- The host scan fails a URL whose scheme is followed by two or more slashes or backslashes, and a protocol-relative URL with a dotted host, in `index.html`, `vite.config.ts` and every file under `src/` and `public/` (and `dist/` with `--dist`); it reads every file except those with an extension on a closed binary list (fonts, images, audio, video, `.pdf`, `.wasm`, `.zip`, `.gz`), which it counts only. It does not read a bare host name, a single-label or IPv6 host, a URL assembled at run time or an encoded slash, and it does not read `scripts/` or `tests/`. In the built JavaScript it allows four named hosts that React ships as message and namespace text, not as requests; it cannot tell a string from a request in minified code. The browser-level test that blocks other origins and the server's content security policy belong to later slices.
- Fonts are not bundled in this shell and the shell sets no font. Vendoring the font files with their licence text is slice S3; see OI-43 in [OPEN_ITEMS.md](../OPEN_ITEMS.md).
- The FastAPI process serves the built `dist/` at `/` and `/assets/*`; this folder starts no other server.
