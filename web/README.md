# web/ — experience plane, the React front end

This folder holds the browser application shell: React, TypeScript and Vite, with no feature UI.

## Rules

- The front end reaches the backend only over HTTP (BE-06).
- No dependency or asset is loaded from a third-party host (FE-05).
- The browser computes no displayed number; it only formats the values it receives.

## Commands

Run from `web/`. `npm ci` installs from `package-lock.json` and needs the network once. `npm run spike:glyphs:install-browser` also needs the network once. The other commands below work without it.

- `npm ci` installs the exact locked dependencies.
- `npm run dev` starts the development server on `127.0.0.1` (port 5173, strict). It is a developer command and is not part of the checks.
- `npm run build` type-checks with `tsc --noEmit` and runs the production build into `dist/`.
- `npm run check` runs the layout check, the exact-version check (FE-01), the import-boundary check (FE-07) and the third-party host scan of the sources (FE-05, DES-24).
- `npm run check:hosts:dist` runs the host scan again over the build output; run it after `npm run build`.
- `npm run check:dev` reads the entry script named in `index.html`, starts the development server on a free loopback port (a port that already answers is reported as a failure), checks that the served page names that script and that the script is served as JavaScript, scans the page for third-party hosts and stops the server.
- `npm run test:checks` runs the tests of the checks above and of the shell files, each with a planted violation.
- `npm run lint` runs ESLint (flat configuration in `eslint.config.js`) with no warning allowed. It also enforces FE-11: in every `.js`, `.mjs`, `.cjs`, `.jsx`, `.ts`, `.mts`, `.cts` and `.tsx` file it reports a reference to `fetch` or `EventSource`, bare or through `window`, `globalThis` or `self`, except in files under `src/api/`.
- `npm run format:check` runs Prettier in check mode (`.prettierrc.json`, `.prettierignore`); it writes nothing.
- `npm run typecheck` runs `tsc --noEmit` for the shell. The glyph spike is type-checked by its own Node test, `spikes/glyphs/tests/typecheck.node-test.mjs`, with `tsc -p spikes/glyphs/tsconfig.json --noEmit`.
- `npm run spike:glyphs:build` builds the synthetic glyph spike into `spikes/glyphs/dist/` for a developer. The browser suite and the recorder do not read that folder.
- `npm run spike:glyphs:install-browser` installs the headless shell the tests launch into the uncommitted folder `data/tools/playwright/` at the repository root; in the CI environment it also installs the system libraries the shell needs, and on any other machine it changes nothing outside the repository. It needs the network once. A missing browser fails and names this command.
- `npm run test:spike:glyphs` builds the spike into a temporary folder, serves that folder on a loopback port and runs the spike browser tests. The pixel comparison runs in the hosted job's own step, or a direct run of the command with `CI=true`, and does not run in `./eii test`, anywhere; a missing or differing baseline fails that run and names the file.
- `npm run spike:glyphs:record` builds the spike into a temporary folder and writes the three evidence screenshots and their hashes under `spikes/glyphs/evidence/`. It does not write `visual-review.md`.
- `npm run spike:glyphs:verify-evidence` checks that record. It accepts a visual review of exactly `pending native review` or `approved`, and it fails on a missing file or a changed image hash.
- `npm run spike:glyphs:capture` runs the suite's own screenshot captures into `data/glyph-captures/` only when `CI` is `true`. The pixel comparison runs in the hosted job's own step, or a direct run of the command with `CI=true`, and does not run in `./eii test`, anywhere; that folder is not the folder the comparison reads. It is not used to make a local failure pass.
- `npm run format` runs Prettier in write mode over the same files as `format:check`. It rewrites files and is run only to apply the formatter.
- `./eii test`, run from the repository root, runs two web suites: `web-checks` (the `*.node-test.mjs` files of `scripts/tests/` and of `spikes/glyphs/tests/`, with `scripts/count-reporter.mjs` as the counting reporter) and `web-unit` (Vitest, `vitest.config.ts`, the files `tests/unit/**/*.test.ts`). No script was added to `package.json` for them. The pixel comparison runs in the hosted job's own step, or a direct run of the command with `CI=true`, and does not run in `./eii test`, anywhere.

## Limits of the checks

- The import-boundary check reads the script files (`.ts .tsx .mts .cts .js .jsx .mjs .cjs`) and style files (`.css .scss .sass .less .styl .pcss`) under `src/`, `tests/` and `eslint-rules/`, the file `vite.config.ts`, and `tsconfig.json`. It does not read `scripts/`. In script files it reads these literal forms: `import ... from`, `export ... from`, `import 'x'`, `require('x')`, `import('x')`, `new URL('x', import.meta.url)`, `import.meta.glob` with a string or an array of strings, and `/// <reference path>` and `/// <reference types>`; strings are read in single or double quotes in every form above, and as backticks without `${` only inside `import()`, `new URL()`, `import.meta.glob()` and `require()`. It reports a template literal with `${`, a name, or any other non-literal first argument of `import()` and `require()` (and a template literal with `${` in `new URL()`). Text inside a comment of a script file is not judged. It is not a JavaScript parser: a regular-expression literal or JSX text that holds a quote can hide the rest of that line, and a path built at run time, a `new Worker` path, a `new URL` or `import.meta.glob` with a name, Sass `@use`, and `vite.config.ts` settings are not read. In style files it reads `@import` and `url()`, and comments are not stripped there.
- The host scan fails a URL whose scheme is followed by two or more slashes or backslashes, and a protocol-relative URL with a dotted host, in `index.html`, `vite.config.ts` and every file under `src/` and `public/` (and `dist/` with `--dist`); it reads every file except those with an extension on a closed binary list (fonts, images, audio, video, `.pdf`, `.wasm`, `.zip`, `.gz`), which it counts only. It does not read a bare host name, a single-label or IPv6 host, a URL assembled at run time or an encoded slash, and it does not read `scripts/` or `tests/`. In the built JavaScript it allows four named hosts that React ships as message and namespace text, not as requests; it cannot tell a string from a request in minified code. The browser-level test that blocks other origins and the server's content security policy belong to later slices.
- The application shell bundles no font and sets no font. The glyph spike, under `spikes/glyphs/`, bundles IBM Plex for the page chrome and Noto for the map labels from those npm packages, and serves the four SIL licence texts from the spike build. See OI-43 in [OPEN_ITEMS.md](../OPEN_ITEMS.md).
- The FastAPI process serves the built `dist/` at `/` and `/assets/*`; this folder starts no other server.
- The FE-11 rule is tested for the forms listed in `scripts/tests/lint-fe11.node-test.mjs`: references to `fetch` and `EventSource`, bare or through `window`, `globalThis` or `self`, in files with the extensions `js`, `mjs`, `cjs`, `jsx`, `ts`, `mts`, `cts` and `tsx`, in any folder of `web/` except `src/api/`. Other ways to reach the network (`XMLHttpRequest`, `WebSocket`, a destructured or computed access, an imported HTTP library) are not claimed. ESLint reads only those eight extensions and skips every other file type without a message; it does not read `dist/`, `spikes/glyphs/dist/` or `node_modules/`. Prettier does not read `dist/`, `package-lock.json`, Markdown, `playwright-report/` or `test-results/`.
- The Vitest suite has one unit test, rendered with `react-dom/server` in the default `node` environment; that suite installs no DOM library (OI-48). The glyph spike uses `@playwright/test` and the headless shell in `data/tools/playwright/`. `tsc` does not read `tests/` or `vitest.config.ts`; ESLint and Prettier do. The Node counting reporter counts each test once: a `describe` is no test, but a skipped `describe` and a file that registers no test each count as one skipped item; a test with failing subtests counts the failing subtests, not the parent; a TODO test counts as skipped; a failing hook counts every test it cancelled as failed. For Vitest, a file that fails without a failed test (import error, empty file, failing hook) counts as one failed test, and the tests a failing hook skips count as skipped. Vitest's JSON reporter does not expose two forms, so the runner cannot judge them and they are left to review and lint: an `it.fails` or `test.fails` test whose body fails as expected is written as passed, with no marker, and a `describe.todo` without a body is omitted (an `it.todo` and a `describe.todo` with a body are reported as TODO and count as skipped). The Python runner counts a test that uses subtests once; Node's runner counts each subtest as a test.
