## Context

The owner's relayed decision of 2026-11-21 22:16 directs slow work into a background lane when possible. The advisor applied it to `tenders_pub`: the supplied run history says the tender acquisition is network-bound and five earlier attempts failed, ending those whole-pack runs. Its consumer is planned in S7-T09. This record makes no claim that the current live run has completed or that the release builder exists.

## Decision

1. **Closed own run.** `./eii build-public --tenders-only` and `--tenders-only --resume` are lead-shell forms. The wrapper requires exactly one `tenders_pub` registry entry, including its source ID and `paged_cards` kind, before acquisition. A missing, duplicate or extra entry, even one on the same host, refuses. It fetches into uncommitted `data/public_cache_tenders/`, with its own `build-run.json`, `build-log.json`, twelve list readings and pages, terms archive and immutable tender archive. Its receipt carries the original retrieval UTC, archive SHA-256 and verified raw terms-body SHA-256. It makes no whole-registry completeness or gate claim.
2. **Ordinary run and pending state.** The ordinary run retains the active registry row, empty `skip_reason` and `pub_tender` declaration. It logs `own_run` and makes no list or terms request on behalf of `tenders_pub`. Other separately registered sources on that host keep their acquisition behavior. With no tender pin, assembly admits `own_run_pending` only for that exact row after the committed S2-T13 confirmation and every registry-side decision-0083 comparison pass. Selection and layer dispatch check this before raw bytes are read. They build no `pub_tender` and no source-table edge. Completeness records `NO_DATA`, reason `own_run_pending`, caveat `tender_fetch_own_run`; S2-T13 records that exact absence with its weight confirmation unchanged. Any other missing pin still fails.
3. **Pick-up.** The lead's main-cache `snapshot_pins.json` names one tender archive hash in the separate cache. Assembly reads that identity only, verifies index, receipt and body, applies the full decision-0083 binding to the present receipt, and checks both awarded-language readings against the main cache's verified intake cut-off, closed full-read reason and workbook SHA-256. Missing, corrupt or mismatched pinned bytes never turn into pending. The receipt's original publisher, basis, retrieval date, terms hash and archive hash flow to `pub_tender`'s source chain. The next ordinary run performs pick-up; there is no assembly-only command. A fresh main run after an earlier completed main run refetches its other entries; an eligible interrupted main run can reuse individually proven completed entries. No elapsed-time saving is asserted.
4. **Existing-result handoff.** Before a new tender fetch, the lead-owned own run checks for a previously pinned main-cache tender archive. It requires a completed tender entry with rehashed original page and list-receipt proofs, the intake fingerprint if that journal recorded one, an immutable archive verified by `read_snapshot`, actual archived terms-body evidence, decision-0083 receipt binding and main-intake equality. An older journal without an intake fingerprint is eligible only when both archived awarded-language readings match the current main intake. It copies only the archive and terms snapshots' index, receipt and body bytes into the separate cache, preserving their hashes and retrieval UTC. It copies no main journal, log or pin. A failed proof writes a closed refusal in the separate log and leaves its journal interrupted; a fresh fetch is a separate later action, never silent adoption. If only completed pages exist, the lead first reviews their original journal/page proofs and actual terms snapshot, calls the existing `archive_pages` with that entry's original retrieval UTC and verified terms hash, reviews the archive, and pins its identity in the main cache. A missing terms proof cannot be invented or restamped.
5. **Resume and gate words.** The separate run's `--resume` uses `RunRecord`: a completed entry of an interrupted run can be reused only after page, receipt and intake proofs pass, retaining its original time; a failed long fetch has no page checkpoint and starts that entry again. Entry-set and seed mismatch and a completed journal refuse. The C-09 gate records either the technical `own_run_pending` absence, never a terms absence, or the selected archive's date, hash, cut-off, pages read, stop page and continuity pages. Tender answers will return `NO_DATA` with that caveat while pending; this does not claim a D4 answer is implemented today.
6. **Start and freeze checks.** On the day S7-T09 starts, its lead verifies that the own-run archive receipt exists with original `retrieved_utc`, `sha256` and `terms_sha256`, that the same hash is pinned, and that the latest successful public assembly's source chain names that identity and records `tenders_pub` in use with `pub_tender` built. The same identity-bound check precedes any freeze. S7-T09 does not start while that assembly reports `own_run_pending`.
7. **Built first, under lead ruling L-1408 (task S2-TSKIP).** Only the ordinary run's `own_run` skip and the pending absence of item 2 are built for the slice S2 gate, where any tender pin in the main cache refuses with `own_run_pickup_unbuilt` and, until decision 0083's rebinding is on the base, the pending binding compares the page's host and a non-empty basis note in place of the full page address and the basis note's words; the tenders-only form of item 1, the pinned pick-up of item 3, the handoff of item 4, the resume of item 5 and decision 0083's review binding follow in the background lane after the gate, ready before S7-T09 starts.

## Value and limits

No planned tender value is dropped if item 6 holds: all six lists, both languages and decision 0069's awarded-list evidence remain in scope. The workbook cut-off is only the newest date reached by that incomplete workbook; the later older-page enrichment remains separate. Until pick-up, no tender is shown. A live fetch, valid real archive, release loading and D4 runtime behavior are not proved by this decision or its invented-input tests.
