## Decision

1. **Accept every evaluated item as a measured spike.** The inventory below preserves the evaluation's baseline and pass wording where it supplies one. “Not specified” is an unresolved measurement contract, not a pass: the owning task records its comparator, metric and acceptance threshold before execution and review, without claiming the owner supplied a missing number. Every spike begins with its blocking-fact audit; a failed audit stops that spike and records why. The audit reads authorised metadata or invented real-shaped fixtures, never real custodian records through a worker. A failed spike keeps its baseline and records the measured result.
2. **A passing method is real-data-ready.** Decision 0036 requires one pipeline, contracts, code and tests for generated and real inputs, a swap test on an invented real-shaped fixture, and re-fit and re-backtest at the go-live gate. Intervals and error come from the method's own backtest or stated procedure. Versions, model hashes where relevant, fixed seeds and written retreat pins follow rule 42, with deterministic CPU fallback. This record meets ASSUMPTION 16's authorisation condition for the wider library-backed list; the implementing task must still read current documentation and write exact pins before use. Only tested code computes a figure of record (rules 16 to 18). Rule 25's intervals, error, cases, drivers, counts, periods, editable criteria and rank-stability requirements remain, read with decision 0035's presentation amendment.
3. **Placement follows the critical path.** Items 2 and 3 have fact-audit preparation before S5 and execution during S5, after its unchanged OI-37 entry condition. Items 1 and 14, including the approved zero-shot challenger test, run on S6-T14's approved commit. Item 7 is a task family after S6-T04 and S8-T05; earlier seed rows enter existing S5 and S6 tasks without a new gate or a backward dependency on S8. Other items belong to the slice that first builds a card they serve; small items are named sub-steps of its existing task. No new S2 or S3 task ID is allocated. Spikes do not hold up delivery of an unchanged baseline: record a blocked or failed outcome and keep it. No existing gate or review is waived.
4. **The question factory is testing and gap-mining, never training.** Build an oracle-labelled taxonomy grid and per-cell coverage; adversarial, metamorphic, property-test and multi-turn families; and a held-out set its authors never see. Deterministic graders decide; a model judge is never a gate. Generation tools may propose cases only. Failures enter catalogue entries, playbooks, paraphrases or refusals through the normal task loop. Build the 200-question Arabic routing set for the Later local-model trigger now. The grid includes the national-table classes in item 8.
