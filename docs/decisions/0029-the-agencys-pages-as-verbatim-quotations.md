## Context

DAT-143 fixes their shape: keys, titles, order, references, links and typed incentive parameters, "never a page's paragraphs"; screen text is rendered by application templates with a link to each page.
- [Decision 0064](0064-the-narrowing-rows-decided.md) item 3 keeps the full-page quotation — the agency's page text shown in full, unchanged, as a quotation with the date read, with no model-written summary or translation (rule 21) — and item 32 restores the rest of the investment sources: the agency's Arabic pages are read, the full-page column is added once this record settles it, and the FDI project-to-area crosswalk is filled by lead review, carried by task S2-T39.
- Part A of task S2-T39 keeps the original page bytes in the uncommitted cache with page language, order, hash and retrieval date, and reads them back unchanged through an explicitly selected manifest; it chose no serialization, release column or rendering. The interim row of section 7.3 still describes the earlier keys and says "In this task the release table `pub_investqa_record` still keeps the rule of DAT-143 (no paragraph column)" (OI-178).
- OI-181 records that the task's inventory holds the English pages only and recommends the Arabic reading once this record lands, because each language shows the agency's own text.
- The tension this record settles: rules 21 to 23, AI-37, AI-111 and FE-121 send every rendered numeral through the Fact chip family, while a verbatim page text holds numerals inside the publisher's own prose that cannot become chips without parsing the text — and parsing is a change.
- [Decision 0026](0026-public-sources-used-in-full-locally.md) item 5 keeps every value of the source out of the repository; the release is not the repository, so the page text lives in the release and the uncommitted cache, and tests keep using synthetic pages of the same shape (DAT-143; [decision 0034](0034-licence-questions-of-public-sources-are-answered-at-a-go-live.md)).

## Decision

1. **The release column: a new Public table `pub_investqa_page`, one row per page and language (RECOMMENDED).**
   Options: A — this table; B — a `page` record type and a `page_text` column on `pub_investqa_record`; C — paired `page_text_en` and `page_text_ar` columns on a page row.
   A is RECOMMENDED: the grain of `pub_investqa_record` is a typed record, not a page; a separate table leaves the closed `record_type` list untouched and keeps DAT-143's "no paragraph column" literally true of the record table. B is refused: it widens the closed list, leaves most record columns null on page rows, and makes the paragraph check need a carve-out on the same table. C is refused: paired columns hide a missing language and invite filling one language from the other, which item 4 forbids.
   Columns (written out in appendix item 2): `page_key` string (lower snake case from the page's path, as `record_key` forms it); `page_language` (`en`, `ar`: the language of the fetched page as the page itself states it); `sequence` int (Y: the page's order in the site's own page list; null where the list gives none); `page_title` string (Y: the page's own title as published; null where the page gives none); `page_url` string (the page's own address, shared with `pub_investqa_record.page_url`); `retrieved_on` date (the retrieval date of the fetched snapshot the row is built from, selected through the explicitly selected manifest of the fetch path); `page_sha256` string (the SHA-256 of the original fetched page bytes, 64 lowercase hexadecimal characters); `extractor` string (`investqa_page_text@1`, the version of the deterministic extraction that produced `page_text`); `page_text` string (the page's own text under item 2; a page whose text fails a release text check of item 5 has no row). The table's provenance is `public`, its evidence status Observed, and `source_id` joins `source_registry` as on every Public table. The page rows join the record rows through `page_url`; no record column changes. DAT-143 is amended by the exact word changes of appendix items 3 and 4.

2. **"In full and unchanged": the versioned deterministic extraction `investqa_page_text@1` over the archived page bytes (RECOMMENDED).**
   The stored text is produced from the original fetched page bytes that the explicitly selected manifest names, never a latest file or mutable pointer, by a deterministic, versioned extraction. The page's text is the visible text of the page's own content region — the element holding the heading-led blocks the record reader parses. Navigation, header, footer, side menus, cookie and consent blocks, scripts, styles, vector graphics, comments and form controls are not the page's text. The extraction takes the region's visible text nodes in document order; text is normalized to Unicode NFC; a whitespace run collapses to one space and a node's ends are trimmed; a node empty after trimming is dropped; a block boundary becomes one newline. Nothing is added, dropped, reordered or reworded beyond that rule; anchor text is kept, and a link's address is not text. A reader proves the text unchanged: `page_sha256` names the original bytes, `extractor` names the version, and the release build re-reads the selected snapshot's bytes, re-runs the recorded version and requires byte-equality with `page_text`; a planted difference fails. Refused alternatives: storing the raw page markup, which is not the page's text and would need run-time sanitization, and storing a picture of the page, which is not text, carries no language mark and fails accessibility.

3. **Rendering: the `source_quotation` component and the `verbatim-quotation` exception to rule 23 (RECOMMENDED).**
   Application templates render the quotation as a quotation block with the source, the date read and the link: the body is the stored `page_text` as one bidirectionally isolated run marked with `lang` and `dir`; the caption is template text — the publisher, the page title, `retrieved_on` as a Fact chip and `page_url` as the link. AI-27 stands: the page's body text never reaches the model; a model may name a record or page key at most, and never receives or emits a character of the text.
   Numerals inside the quotation are the publisher's own words and cannot become Fact chips without parsing, which item 2 forbids. The narrow, named exception **`verbatim-quotation`** to rule 23 applies: a numeral that is a character of the stored text of `pub_investqa_page.page_text` may render inside the body element of the `source_quotation` component, and nowhere else. Its limits: the exception is bound to that one element of that one component; the text passes to it as one opaque run, so nothing parses, extracts, re-renders or reuses a numeral from it; it fills no fact slot, claim slot, question slot, stage directive or model input; every numeral outside it stays in the Fact chip family, with the build-time lint and the running-page provenance audit unchanged; and the body is visually and structurally a quotation under its source and date, so its numbers are visibly the publisher's own words. Refused alternatives: extracting the numerals of the quotation into chips (a derivation over text, which changes what is shown and lets code compute on words) and removing digits (not "in full"). Tests the exception carries: a component test renders the body byte-equal to the stored text inside the isolate; a planted numeral outside the element fails the unchanged lint; a planted brief, claim, question or directive carrying page text or a slice of it is refused; AI-37's template numeral scan is unchanged and a planted template numeral fails; a `page_text` value planted as a fact's value is refused by the fact schema, because it is no `published_text` of DAT-155's closed form.

4. **Both languages.** Each language shows the agency's own text of that language, and never a translation: a translated line is not the agency's own words, and it is generated text no rule admits (rule 21; the KEEP's "no translation" of decision 0064 item 3). The Arabic quotation renders right-to-left in its own isolate, `dir="rtl"` and `lang="ar"`, in the publisher's order; digits and Latin runs inside it stay exactly as published, with no conversion, and only the chrome around the quotation mirrors — Arabic mirrors chrome and reading order, not numerals. A page missing in one language has no row for it: the catalogue's missing-page sentence, a template, shows the page as missing with its link and the date read, and the text is never filled from the other language (OI-181).

5. **The checks the column passes before release.** `page_text` is a string column like every other and keeps every scan a string column keeps: the release text-token scan reads it as text, so a bare run of exactly eight or eleven digits fails it (TST-142; rule 9); the contact scan that every other string column keeps applies to it (the `pub_tender` row of section 7.3); and the release scan of PRV-72 reads it for synthetic identifiers, canary markers and register numbers. A page whose text holds such a token is refused whole: its `pub_investqa_page` row is not written, the build report records the page key, the check and the reason, and the page's typed records still show with their link. Nothing is cleaned into the column: unlike a tender's title fields, which are record text cleaned under a stated rule, this column is the page itself, and verbatim admits no redaction. Refusal per page is RECOMMENDED over refusing the whole build — one contact block on one page would remove every page's quotation while the shipped release still carries no token, so the guard is unweakened — and over exempting the column, a weakening rule 12 forbids: a planted token must still refuse. On a refusal the release ships without that page's text, the build report names the page and the reason, and the display shows the missing-page state of item 4. The table's rows enter the public-totals inventory of PRV-115 as `row:` entries with status `source_only` — a page text is no applicable total — beside the registry row's `source:` entry.

6. **What part B builds and tests.** Part B of task S2-T39 lists and reads the agency's Arabic pages through the normal seam (OI-181); runs `investqa_page_text@1` over the bytes of each explicitly selected snapshot for both languages and writes `pub_investqa_page`; applies this record's appendix to document 03 once (OI-178); and adds the `source_quotation` component, its caption templates and the `verbatim-quotation` exception to the catalogue and to the lint's allow-list. Its tests use synthetic pages of the same shape in both languages, and nothing fetched is committed: determinism — the same bytes give the same text, re-extraction is byte-equal with the stored column, and a planted reordered element changes the text; refusals — a planted bare run of exactly eight and one of exactly eleven digits, a planted e-mail-shaped token, and a planted text that differs from the bytes the hash names each refuse the page; languages — a page with no Arabic row shows the missing template, the Arabic quotation renders right-to-left inside its isolate against a reviewed screenshot, and planted English text in the Arabic run is refused; rendering — the body is byte-equal, a planted numeral outside the component fails the lint, page text planted in a claim, slot or directive is refused, and a planted template numeral fails AI-37's scan; and the inventory — every row enters PRV-115 as `source_only`.

## What would change this decision

- A changed page structure the recorded extractor cannot read: the recorded version stays, and a new element set is a new extractor version named on the rows, with the contract revision of DAT-120 and DAT-121 where the column list changes.
- A publisher terms change on the going-live list of decision 0026 item 4 and decision 0034 item 1.
- An owner decision on the quotation or on the named exception.

## What is not decided

- The exact element list of `investqa_page_text@1` is fixed in part B's reviewed parser change on the synthetic page of the same shape; this record fixes the rule it follows — the page's own content region, its visible text nodes in document order and the stated whitespace rule — and that its version is recorded on every row.
- A page's own heading-led blocks may repeat inside `page_text` what `pub_investqa_record` holds as typed fields: they do, because the quotation holds the whole content region, and the typed fields still come only from the record table.
- The going-live position of the source, which stays on the list of [17_DEPLOYMENT_HARDENING.md](../17_DEPLOYMENT_HARDENING.md) (decision 0026 item 4).
